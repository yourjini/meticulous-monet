# AI_CODE_REVIEW.md — AI가 만든 코드를 배포하기 전에

> AI 코딩 도구는 "작동하는 코드"는 잘 만들지만 "안전한 코드"는 아직도 사람이 확인해야 한다.
> 이 문서는 **배포 전 4가지 관문** 과 **스스로에게 던질 3가지 질문** 을 정의한다.

---

## 스스로에게 던질 3가지 질문

1. **접근 제어가 서버 측에 있는가, 클라이언트 측에만 있는가?**
   - 클라이언트 JS / 프론트엔드 라우터 가드만 있는 상태라면 **무방비**다.
2. **외부 API로 데이터를 보내고 있다면, 어떤 데이터가 어디로 가는지 파악하고 있는가?**
   - "어떤 필드가 / 어느 엔드포인트로 / 어떤 조건에서" 까지 한 줄로 답할 수 있어야 한다.
3. **AI가 만들어준 코드의 아키텍처를 내가 설명할 수 있는가?**
   - 설명하지 못하면 아직 배포할 준비가 안 된 것이다. 사람이 요약 가능해질 때까지 리팩터링·문서화한다.

---

## 배포 전 4가지 관문 (필수)

하나라도 "모름/미확인"이면 배포 **중단**.

### 관문 1. 인증 (Authentication)
- [ ] 보호된 리소스에 접근할 때 **서버가** 요청 주체를 검증한다.
- [ ] 토큰/세션의 만료·갱신·폐기 경로가 존재한다.
- [ ] 관리자/일반 사용자 경로가 분리되어 있다.
- [ ] 테스트 계정 / 디버그 우회 경로가 프로덕션에 남아있지 않다.

### 관문 2. 암호화 (Encryption)
- [ ] 전송 구간: 모든 외부 호출이 HTTPS/TLS 위에서 이뤄진다.
- [ ] 저장 구간: 민감 필드(토큰, 비밀번호 해시, 개인정보)는 at-rest 암호화되거나 적절히 해시된다.
- [ ] 비밀번호는 bcrypt/argon2/scrypt 등으로 해시되고, 평문 로깅이 없다.
- [ ] 키·시크릿은 환경변수/비밀관리자에서 주입된다. 레포/이미지/로그에 박혀있지 않다.

### 관문 3. 접근 권한 (Authorization / Access Control)
- [ ] 모든 API 엔드포인트가 **서버 측** 권한 검사를 거친다 (IDOR 방어).
- [ ] 사용자가 자기 리소스만 조회/수정할 수 있게 `userId` 또는 테넌트 체크가 있다.
- [ ] 관리자 API 는 별도 역할 검증이 있다.
- [ ] 프론트 라우터 가드 **이외에** 실제 방어가 있다. (UI 숨김 ≠ 접근 제어)
- [ ] 파일 업로드·다운로드의 경로 탐색(`../`)·임의 파일 접근이 막혀있다.

### 관문 4. 데이터 흐름 (Data Flow)
- [ ] 어떤 데이터가 어느 경로로 이동하는지 한 장의 다이어그램 / 목록으로 정리했다.
- [ ] 외부로 나가는 모든 호출(AI API, 분석 도구, 제3자 SaaS)의 **보내는 필드 목록**을 안다.
- [ ] PII/민감 데이터가 외부로 나가는 경우 **DPA(데이터 처리 계약)** 또는 법적 근거가 있다.
- [ ] 로그·에러 리포팅에 민감 필드가 마스킹된다 (`Authorization`, `password`, `ssn`, `card` 등).
- [ ] 테스트 / 개발 환경의 데이터셋이 실제 사용자 데이터가 아니다.

---

## AI 에이전트 자동화 작업(Routines) 전용 체크

자동 반복 실행되는 에이전트 작업은 한 번의 실수가 **매분/매시간** 재현된다.

- [ ] 이 작업이 **어느 레포**에 접근하는지 명시되어 있다.
- [ ] 이 작업이 **어느 외부 서비스**에 연결되는지 명시되어 있다.
- [ ] 이 작업에 주어진 **토큰의 스코프**가 최소 권한이다 (read-only면 충분한지, write가 정말 필요한지).
- [ ] 실패/이상 동작 시 **중단 조건 / 알림 경로** 가 있다.
- [ ] 작업 로그를 사람이 주기적으로 훑는 루틴이 있다.

---

## 실행 액션 (오늘 당장)

1. 이미 AI 에이전트로 만든 프로젝트가 있으면, **백엔드 접근 제어**부터 본다. 클라이언트 JS에만 의존하는 구간이 있으면 서버 측 검증을 추가한다.
2. 외부 API 호출을 하는 코드를 `grep` 해서, 보내는 필드 목록을 한 파일에 정리한다 (`docs/DATA_FLOW.md` 권장).
3. 배포 파이프라인(또는 최소한 로컬 배포 스크립트)에 이 4가지 관문 체크를 통과해야 배포되도록 **체크포인트**를 건다.

> **핵심**: AI가 생성한 코드가 무엇을 하는지 **내가** 설명할 수 없다면, 아직 배포 준비가 안 된 것이다.
