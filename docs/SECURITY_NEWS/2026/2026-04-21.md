# 2026-04-21 — AI 코딩 에이전트 배포 시 "서버 측 접근 제어 누락" 사례 교훈

## TL;DR
AI 코딩 도구로 만든 앱에서 **클라이언트 측 라우터 가드만** 두고 서버 측 권한 검사를 빼먹는 사고가 반복된다.
본 레포는 배포 전 "인증·암호화·접근권한·데이터흐름" 4대 관문을 **필수 체크리스트**로 고정한다.

## 무슨 일이 있었나
- AI 에이전트로 빠르게 프로토타이핑 → 프론트엔드만 보고 "권한 체크 된다"고 판단 → 배포.
- 실제로는 API 엔드포인트가 무인증으로 열려 있어 타인의 데이터 열람/수정이 가능했던 사례가 여러 건 보고됨.

## 왜 일어났나 (근본 원인)
1. AI 가 생성한 코드의 **아키텍처를 사람이 설명하지 못한 채** 배포.
2. UI 레벨의 버튼 숨김을 "접근 제어"로 착각.
3. 자동화 에이전트 작업(Routines)이 어느 레포·어느 서비스에 닿는지 파악하지 않음.

## AI 코딩/Claude 와의 연결 고리
- AI 는 "작동하는 코드"는 잘 내놓지만 "안전한 코드"는 아직 사람이 확인해야 한다.
- 특히 에이전트 자동화는 한 번의 실수가 매분/매시간 재현된다.
