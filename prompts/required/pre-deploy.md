# prompts/required/pre-deploy.md — 배포 직전 4대 관문

- **언제 쓰나**: 스테이징/프로덕션 배포 직전.
- **예상 소요시간**: 5~10분.
- **근거**: [`../../docs/AI_CODE_REVIEW.md`](../../docs/AI_CODE_REVIEW.md)

---

## Claude 에게 붙여넣을 프롬프트

```
배포하기 전에 아래 4대 관문을 순서대로 검증해. 하나라도 "확인 실패/모름"이면 배포 중단.

관문 1. 인증 (Authentication)
- 보호된 엔드포인트/화면이 **서버 측**에서 요청 주체를 검증하는 코드를 grep 해서 보여줘.
- 토큰 만료·갱신·폐기 경로가 코드상 존재하는지 확인.
- 테스트/디버그 우회(예: `if process.env.NODE_ENV==='dev'`) 가 남아있는지 찾아.

관문 2. 암호화 (Encryption)
- 외부 호출 URL이 전부 https 인지 grep.
- 비밀번호가 bcrypt/argon2/scrypt 로 해시되는지 찾아. 평문 로깅 여부 확인.
- 키/시크릿이 환경변수로만 주입되는지 확인. 코드에 박힌 상수가 있으면 보고.

관문 3. 접근 권한 (Authorization)
- 모든 API 라우트에 서버 측 권한 검사가 있는지 확인. 특히 "userId/테넌트" 기반 필터.
- 클라이언트 측 라우터 가드만 있고 서버 측이 없으면 **명시적으로 경고**.
- 파일 업로드/다운로드에서 `../` 경로 탐색 방어 여부 확인.

관문 4. 데이터 흐름 (Data Flow)
- 외부로 나가는 모든 호출(AI API, 분석 SaaS, 결제 등) 목록과 보내는 필드를 표로 보여줘.
- PII/민감 필드가 포함되어 있으면 별도로 강조.
- 로그·에러 리포팅이 민감 필드(Authorization, password, ssn, card 등)를 마스킹하는지 확인.

마지막 한 줄 질문:
"이 코드의 아키텍처를 사용자 본인이 한 문단으로 설명할 수 있는가?"
"아니오" 라면 배포를 막고, 먼저 요약 노트를 작성하자고 제안해.
```
